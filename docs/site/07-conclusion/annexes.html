Installation et diagnostic (jour 1)

# Installation
curl -fsSL https://claude.ai/install.sh | bash       # natif (recommandé)
npm install -g @anthropic-ai/claude-code             # voie npm

# Environnement
export ANTHROPIC_API_KEY="sk-ant-…"
export HTTPS_PROXY=http://proxy.entreprise.example:8080
export NO_PROXY="localhost,127.0.0.1,.entreprise.example"
export NODE_EXTRA_CA_CERTS=/etc/ssl/certs/entreprise-ca.pem
export ANTHROPIC_BASE_URL=http://llm-gateway.entreprise.example:4000  # passerelle

# Vérifications
claude --version
claude doctor

Commandes de session

Commande Rôle
/init génère un premier CLAUDE.md
/model change de modèle (léger / intermédiaire / supérieur)
/context remplissage de la fenêtre
/compact compacter à une frontière de phase
/clear repart de zéro
/cost jetons et coût de la session
/status compte, modèle, santé MCP
/memory éditer CLAUDE.md et fichiers de contexte
/mcp état des serveurs MCP
/skills compétences disponibles

Règle des modèles : léger pour corriger/expliquer, intermédiaire par défaut, le plus capable pour concevoir et relire la sécurité.

Permissions (settings.json)

{
  "permissions": {
    "allow": ["Bash(bash -n *)", "Bash(shellcheck *)"],
    "ask":   ["Bash(git commit *)"],
    "deny":  ["Read(.env)", "Read(.env.*)",
              "Bash(git push *)", "Bash(docker system prune*)"]
  }
}

Hiérarchie : deny > ask > allow > mode courant. Jamais --dangerously-skip-permissions.

Bac à sable intégré

{
  "sandbox": {
    "enabled": true,
    "autoAllowBashIfSandboxed": true,
    "filesystem": { "allowWrite": ["/tmp/build"], "denyRead": ["~/.ssh"] },
    "network": { "allowedDomains": ["github.com", "pypi.org"] }
  }
}

  -f ./custom_sbx/docker-compose.yml run --rm claude

# Variante microVM sbx
bash ./scripts/run-claude-sandbox.sh --dry-run   # vérifier d'abord
bash ./scripts/run-claude-sandbox.sh             # créer/rejoindre
sbx ls && sbx exec -it claude-admin-lab bash
sbx stop claude-admin-lab && sbx rm claude-admin-lab
sbx policy log                                   # tentative réseau bloquée
sbx secret set github && sbx secret ls           # secrets injectés

Le workflow en six phases

Phase Action Droits
1. Cadrage besoin, limites, critères d'acceptation lecture
2. Plan étapes et tests, validé par l'humain lecture seule
3. Implémentation script défensif (skill) écriture
4. Consolidation corrections retenues, écarts consignés écriture
5. Revue parallèle portabilité / Bats / ShellCheck / cible rapports
6. Validation preuves puis revue humaine du diff exécution

Prompts d'amorçage :

> Lis CLAUDE.md, puis définis entrées, sorties, OS cibles, droits requis,
  données sensibles, conditions d'échec, journalisation et critères
  d'acceptation. Propose un plan de mise en œuvre et de test. Ne modifie rien.

> Utilise des sous-agents en parallèle, sans modifier de fichier :
  1. portabilité POSIX ; 2. tests Bats ; 3. ShellCheck ; 4. inventaire cible.
  Retourne fichier, problème, impact, correctif proposé.

Contrôles minimaux avant livraison

bash -n scripts/mon-script.sh
shellcheck scripts/mon-script.sh
bats tests/

Puis --dry-run sur cible isolée, puis exécution réelle validée.

Gabarit d'en-tête de script

#!/usr/bin/env bash
#
# mon-script.sh — Une phrase : ce que fait le script.
# Usage     : mon-script.sh [options] [cible]
# Effets    : lecture seule / écrit dans /var/log/…
# Sorties   : 0 OK, 1 anomalie, 2 erreur d'usage.
# Contexte  : origine assistée, revue, tests bats associés.
#
set -euo pipefail

Interdits permanents

  • Aucun secret dans un prompt, un script, un fichier versionné.
  • Aucune commande destructive sans --dry-run et cible de test.
  • Jamais de suppression non bornée (rm -rf sans racine explicite).
  • Jamais de session en contournement global de permissions.
  • Toujours relire le diff, jamais seulement le résumé de l'agent.

A

AFK (away from keyboard) — Mode de travail où l'utilisateur lance une session puis laisse l'agent travailler sans surveillance. Les vérifications automatisées et la revue humaine finale du diff remplacent l'attention humaine pendant l'exécution.

Agent — Le modèle + son harnais + ses outils : l'entité qui lit, écrit et exécute pendant une session.

Artefact de transfert (handoff artifact) — Document écrit dans l'environnement par une session et lu par une autre : spécification, ticket, plan. Il compense le fait que le modèle est sans état.

AX (expérience agent) — Qualité de préparation d'une base de code pour qu'un agent y travaille bien : vérifications rapides, structure prévisible, contexte toujours chargé mais court. Pendant de la DX pour les humains.

B

Bac à sable (sandbox) — Frontière système qui limite ce que les commandes exécutées par l'agent peuvent atteindre : fichiers, réseau, capacités du noyau. Complète les permissions, qui elles contrôlent la décision.

Bash strict — Ensemble d'options set -euo pipefail : échouer vite et fort plutôt que de continuer à moitié. Exigence de base des scripts du dépôt.

Bats — Cadre de tests automatisés pour scripts Bash : cas nominal, options invalides, fichiers absents, codes de retour.

C

CLAUDE.md — Fichier chargé au début de chaque session par Claude Code : la feuille de route permanente du projet pour l'agent (commandes, conventions, interdits). Court et déclaratif.

Compactage (/compact) — Résumé de l'historique de session qui amorce une nouvelle fenêtre de contexte. Avec perte : ce que le résumé omet disparaît. À déclencher manuellement aux frontières de phase.

Contexte — Tout ce que le modèle voit : instructions système, CLAUDE.md, historique, fichiers lus, résultats de commandes.

Contexte, fenêtre de — Taille maximale du contexte, exprimée en jetons. Au-delà : compactage ou réinitialisation.

D

Divulgation progressive — Ne charger que le contexte dont l'agent a besoin à cet instant, le reste derrière des pointeurs. Économise des jetons et évite la dilution des instructions.

DX (expérience développeur) — Facilité avec laquelle une base de code permet aux humains de bien travailler. Se recouvre en partie avec l'AX, diverge sur la connaissance tribale.

F

Frontière de phase — Moment naturel d'une session (plan établi, script généré, tests passés) où compacter perd le moins. L'opposé : le milieu d'un refactoring.

H

Harnais (harness) — L'outil qui enrobe le modèle : découpage du contexte, appel des outils, affichage. Claude Code est un harnais.

Hook — Commande locale exécutée à un événement précis du cycle de l'agent (avant ou après un appel d'outil). Sert à journaliser et à lancer automatiquement les contrôles.

Humain dans la boucle — Mode de travail où l'utilisateur suit la session en temps réel et réoriente en une phrase. S'oppose au mode AFK.

J

Jeton (token) — Unité de découpage du texte, facturée et consommée. Les jetons d'entrée se paient à chaque tour ; un contexte long se repaie tant qu'il n'est pas compacté.

K

Kit (sbx) — Dossier déclaratif qui étend l'agent de base d'un bac à sable microVM : variables, liste blanche de domaines, secrets, installation et démarrage.

M

Modèle — Le réseau de neurones entraîné qui génère le texte. Sans état : il ne se souvient de rien entre deux sessions. Gammes courantes : léger (tâches simples), intermédiaire (défaut), le plus capable (conception).

MCP (Model Context Protocol) — Protocole qui connecte l'agent à des sources d'outils externes : SSH, documentation, forges. Déclaré dans .mcp.json ; les autorisations ciblent l'outil (mcp__serveur__outil).

microVM (sbx) — Machine virtuelle complète pilotée par hyperviseur, avec son système de fichiers et son propre démon Docker. Niveau d'isolation le plus solide.

P

Permission (allow / ask / deny) — Règle qui contrôle l'usage d'un outil par l'agent. deny prévaut sur allow, qui prévaut sur le mode courant.

Pointeur de contexte — Mention d'une ligne qui renvoie vers un document sans l'intégrer : « publication : lire d'abord docs/runbook-deploy.md ». Unité de base de la divulgation progressive.

Prompt — La demande adressée à l'agent, avec son contexte. Ne contient jamais de secret ni de donnée nominative non anonymisée.

R

Revue automatisée — Rapport d'un agent sur le travail d'un autre. C'est un jugement, pas une vérification : elle peut se tromper et se vérifie sur la source primaire (le code).

Revue humaine — Lecture du diff produit par l'agent. Lire le résumé de l'agent ne compte pas : la narration n'est pas l'artefact.

S

Session — Une conversation continue avec l'assistant, du démarrage jusqu'à la sortie.

Skill (compétence) — Unité de savoir-faire (fichier SKILL.md + annexes) chargée seulement quand la tâche la concerne. Seuls nom et description occupent le contexte par défaut.

Source primaire / secondaire — La source primaire est le code, le test, la transcription. La source secondaire (rapport, résumé, documentation) la raconte et peut dériver ou omettre : les faits importants se vérifient sur la primaire.

Spécification — Artefact de transfert décrivant un travail sur plusieurs sessions : objectif, contraintes, décisions, tickets. Se découpe en tickets tenables chacun dans une session.

Sous-agent — Agent lancé par l'agent principal, avec sa propre fenêtre de contexte, qui rend un rapport. Ne peut pas lancer d'autres sous-agents.

sbx — Outil d'orchestration des microVM Docker : création (sbx run), liste, exécution, arrêt, destruction, politique réseau, secrets.

T

Ticket — Artefact de transfert qui délimite une session de travail : objectif, critères d'acceptation, pointeurs de contexte. Taille maximale : une session.

Trap (Bash) — Gestionnaire de nettoyage appelé à la sortie du script : aucun fichier temporaire orphelin après interruption.

V

Vérification automatisée — Contrôle déterministe (test, linter, compilation) : même entrée, même verdict. Le seul signal qui permet à l'agent de s'autocorriger sans humain.

--dry-run — Option de simulation : la commande affiche ce qu'elle ferait sans le faire. Par défaut sur toute commande destructive du dépôt.
